## 📖 Introduction
A Linux server is only as good as its underlying processes. As a system administrator, you need to know how to monitor resource consumption, inspect what services are running, terminate misbehaving applications, and diagnose network health. 

This module covers the core toolkit used to keep a Linux environment stable, performant, and online.

---

## 1. System & Memory Information

### free -h (Memory Info)
The `free` command displays the total, used, and available physical and swap memory on your system. Adding the `-h` (human-readable) flag formats the output into Megabytes and Gigabytes.

**Syntax:**
```bash
free -h
```

**Example Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# free -h
               total        used        free      shared  buff/cache   available
Mem:            7.8Gi       2.1Gi       3.4Gi       150Mi       2.3Gi       5.2Gi
Swap:          2.0Gi          0B       2.0Gi
```
*The output reveals that out of 7.8GB of total RAM, 5.2GB is currently available for applications to use.*

---

### df -h (Disk Space Info)
The `df` (disk free) command reports the amount of disk space available on your file system partitions. Adding `-h` makes it readable.

**Syntax:**
```bash
df -h
```

**Example Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   14G   34G  29% /
tmpfs           3.9G     0  3.9G   0% /dev/shm
```
*The command shows that the root partition (`/`) has 50GB total capacity, with 29% currently utilized.*

---

### top / htop (Interactive Process Viewer)
`top` provides a real-time, dynamic view of running system tasks and resource usage (CPU and RAM). `htop` is its modern, color-coded, interactive equivalent.

**Syntax:**
```bash
top
htop
```
*(Opens a live dashboard. Press `q` to exit back to the terminal).*

## 2. Process Control & Services (`systemctl`)

Modern Linux distributions manage background services (like web servers, databases, and network daemons) using `systemd`. The `systemctl` command controls these services.

### systemctl status / start / stop

**Syntax:**
```bash
systemctl [action] service_name
```

**Examples:**
```bash
systemctl status nginx     # Check if Nginx is running
systemctl start nginx      # Boot up the Nginx service
systemctl stop nginx       # Shut down the Nginx service
```

**Example Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# systemctl status nginx
● nginx.service - A high performance web server and a reverse proxy server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled; preset: enabled)
     Active: active (running) since Mon 2026-08-17 10:00:00 IST; 2h ago
   Main PID: 1250 (nginx)
      Tasks: 2 (limit: 9420)
```
*The command confirms that the Nginx web server is actively running under Process ID (PID) 1250.*

## 3. Active Jobs & Background Tasks

### sleep & jobs
The `sleep` command pauses execution for a specified number of seconds. If you run it in the background by appending an ampersand (`&`), it becomes an active terminal job.

**Syntax & Example:**
```bash
sleep 300 &
jobs
```

**Example Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# sleep 300 &
[1] 1422
┌──(root㉿localhost)-[/home/kali]
└─# jobs
[1]+  Running                 sleep 300 &
```
*The `jobs` command displays background tasks currently tied to your active terminal session.*

## 4. Terminating Processes (`kill`, `pkill`, `pgrep`)

### pgrep (Find Process ID)
Before killing a process, you often need its Process ID (PID). `pgrep` searches for running processes by name and outputs their numeric PID.

**Syntax:**
```bash
pgrep process_name
```

**Example Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# pgrep nginx
1250
1251
```

---

### kill -9 & pkill
If a program freezes or refuses to close, you must terminate it. `kill` takes a specific PID. `kill -9` sends a mandatory, uncatchable kill signal. `pkill` allows you to kill a process directly by its name without looking up the PID.

**Syntax & Examples:**
```bash
kill -9 1251       # Force kills process 1251
pkill nginx        # Force kills all processes named 'nginx'
```

## 5. Network Troubleshooting & Diagnostics

### ping
Tests reachability to another host over an IP network by sending ICMP echo requests.

**Syntax & Example:**
```bash
ping -c 4 8.8.8.8
```

**Example Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# ping -c 4 8.8.8.8
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=115 time=14.2 ms
--- 8.8.8.8 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3005ms
```

---

### ifconfig / ip
Inspects network interface configurations, active IP addresses, and hardware states.

**Syntax:**
```bash
ip a
ifconfig
```

---

### traceroute
Traces the exact network path (hops) packets take to reach a destination server.

**Syntax & Example:**
```bash
traceroute google.com
```

## 6. Power State Management

When maintenance is complete, you may need to restart or shut down the machine safely.

### reboot & shutdown

**Syntax & Examples:**
```bash
reboot                  # Restarts the system immediately
shutdown -h now         # Halts/shuts down the machine immediately
shutdown -h +10         # Shuts down the system in 10 minutes
```

---

## 🎯 Final Takeaways

Managing system processes ensures your infrastructure remains performant and resilient. 
* Use **`top`** or **`free -h`** to diagnose bottlenecks.
* Use **`systemctl`** to control application lifecycles.
* Use **`kill -9`** as a last resort for frozen apps.

With processes and services under control, you are ready to advance to **Module 6: Package Managers and Patchers** to install and update software.
