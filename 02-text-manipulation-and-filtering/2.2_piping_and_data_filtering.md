## 📖 Introduction
If the previous module taught you how to read a file, this module teaches you how to interrogate it. Linux allows you to take the output of one command and "pipe" it directly into another command. 

By chaining together small, specialized programs (like `grep`, `awk`, and `sort`), you can filter massive amounts of text, extract specific data points, and reshape outputs without ever opening a text editor.

---

## 1. The Pipe Operator (`|`)

The pipe `|` (usually found above the Enter key) is the ultimate connector. It takes the **Standard Output (stdout)** of the command on the left and passes it as the **Standard Input (stdin)** to the command on the right.

**Example Concept:**
```bash
command_1 | command_2 | command_3
```
*(We will use the pipe heavily in the commands below!)*

## 2. Searching & Finding Data

### grep (Global Regular Expression Print)

`grep` is used to search for a specific word or pattern inside a file (or an output stream). It prints the entire line where the match is found.

**Syntax:**
```bash
grep "search_term" filename
cat filename | grep "search_term"
```

**Example:**
```bash
grep "root" /etc/passwd
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# grep "root" /etc/passwd
root:x:0:0:root:/root:/bin/bash
```

*   The `grep` command searched the `/etc/passwd` file and only printed the line containing the word "root".

---

### egrep (Extended Grep)

`egrep` acts like `grep` but allows for advanced regular expressions, such as searching for multiple different words at the same time using the `|` (OR) symbol.

**Syntax:**
```bash
egrep "term1|term2" filename
```

**Example:**
```bash
egrep "root|kali" /etc/passwd
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# egrep "root|kali" /etc/passwd
root:x:0:0:root:/root:/bin/bash
kali:x:1000:1000:kali,,,:/home/kali:/bin/zsh
```

*   The `egrep` command successfully pulled lines matching either "root" OR "kali" in a single search.

---

### history | grep

This is a classic sysadmin combo. Instead of scrolling through hundreds of past commands, you pipe your `history` into `grep` to find exactly what you typed earlier.

**Syntax:**
```bash
history | grep "forgotten_command"
```

**Example:**
```bash
history | grep "apt"
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# history | grep "apt"
  105  apt update
  112  apt install nginx
  140  history | grep "apt"
```

*   The terminal output filters your entire command history to only show lines where you used the `apt` package manager.

---

### find

`find` is a powerful tool to search for actual files and directories across the filesystem based on names, sizes, or modification dates.

**Syntax:**
```bash
find /path/to/search -name "filename"
```

**Example:**
```bash
find /var/log -name "*.log"
```

**Output:**
```bash
┌──(root㉿localhost)-[/]
└─# find /var/log -name "*.log"
/var/log/auth.log
/var/log/kern.log
/var/log/dpkg.log
```

*   The `find` command scoured the `/var/log` directory and printed the absolute paths of every file ending in `.log`.

---

### updatedb & locate

While `find` searches live, `locate` is much faster because it searches a pre-built database of your filesystem. You must run `updatedb` first to refresh the database.

**Syntax:**
```bash
updatedb
locate filename
```

**Example:**
```bash
updatedb
locate nginx.conf
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# updatedb
┌──(root㉿localhost)-[/home/kali]
└─# locate nginx.conf
/etc/nginx/nginx.conf
```

*   After updating the index, `locate` instantly found the configuration file without having to manually scan the hard drive.

## 3. Sorting & Counting

### sort & sort -r

The `sort` command organizes text files line by line, alphabetically or numerically. Adding the `-r` flag sorts it in reverse.

**Syntax:**
```bash
sort filename
sort -r filename
```

**Example:**
```bash
sort -r names.txt
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# sort -r names.txt
Zack
Suryansh
Alice
```

*   The `sort -r` command reorganized the names in reverse alphabetical order directly in the terminal.

---

### sort | uniq

The `uniq` command removes duplicate lines from a file, but **it only works if the duplicates are directly next to each other**. Therefore, you must always `sort` the file first, then pipe it into `uniq`.

**Syntax:**
```bash
sort filename | uniq
```

**Example:**
```bash
sort ip_addresses.txt | uniq
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# sort ip_addresses.txt | uniq
192.168.1.10
192.168.1.50
192.168.1.99
```

*   The pipeline sorted the IP addresses, placing duplicates adjacently, allowing `uniq` to cleanly filter them out.

---

### wc -l (Word Count - Lines)

The `wc` command counts words, bytes, or lines. The `-l` flag specifically counts the number of **lines** in a file or output stream.

**Syntax:**
```bash
wc -l filename
command | wc -l
```

**Example:**
```bash
wc -l /etc/passwd
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# wc -l /etc/passwd
42 /etc/passwd
```

*   The `wc -l` command confirmed there are exactly 42 lines (and therefore 42 user accounts/services) in the passwd file.

## 4. Text Manipulation (The Heavy Hitters)

### cut

`cut` extracts specific columns or sections from a file. You use `-d` to define the delimiter (what separates the columns, like a comma or colon) and `-f` to pick the field (column) number.

**Syntax:**
```bash
cut -d'delimiter' -f[number] filename
```

**Example:**
```bash
cut -d':' -f1 /etc/passwd | head -n 3
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# cut -d':' -f1 /etc/passwd | head -n 3
root
daemon
bin
```

*   The `cut` command split the file at every colon (`:`) and extracted only the 1st column (the usernames). We then piped it to `head` to only show the top 3.

---

### awk -F

`awk` is actually a complete programming language used for advanced text processing. Similar to `cut`, `-F` defines the separator, and `{print $1}` dictates which column to print. `awk` is generally smarter and handles complex spacing better than `cut`.

**Syntax:**
```bash
awk -F'separator' '{print $column_number}' filename
```

**Example:**
```bash
awk -F':' '{print $1 " - " $7}' /etc/passwd | head -n 3
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# awk -F':' '{print $1 " - " $7}' /etc/passwd | head -n 3
root - /bin/bash
daemon - /usr/sbin/nologin
bin - /usr/sbin/nologin
```

*   `awk` extracted column 1 (username) and column 7 (default shell), and perfectly formatted them together with a dash.

---

### sed (Stream Editor) - Print Specific Line

`sed` modifies text on the fly. You can use it with `-n 'Xp'` to print one specific line number from a massive file without reading the rest of it.

**Syntax:**
```bash
sed -n '[line_number]p' filename
```

**Example:**
```bash
sed -n '3p' /etc/passwd
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# sed -n '3p' /etc/passwd
bin:x:2:2:bin:/bin:/usr/sbin/nologin
```

*   The `sed` command instantly extracted and printed exactly line number 3.

---

### sed (Stream Editor) - Find & Replace

The most common use of `sed` is for substituting (replacing) text. The `s` stands for substitute, and the `g` at the end stands for global (replace all instances on the line).

**Syntax:**
```bash
sed 's/old_word/new_word/g' filename
```

**Example:**
```bash
echo "I love Windows" | sed 's/Windows/Linux/g'
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# echo "I love Windows" | sed 's/Windows/Linux/g'
I love Linux
```

*   `sed` intercepted the output stream, dynamically found the word "Windows," and replaced it with "Linux" before printing it to the screen.

---

### tr (Translate)

The `tr` command translates or deletes characters. It is frequently used to change uppercase to lowercase, or to remove unwanted symbols.

**Syntax:**
```bash
tr 'old_chars' 'new_chars'
tr -d 'char_to_delete'
```

**Examples:**
```bash
echo "hello world" | tr '[:lower:]' '[:upper:]'  # Converts to uppercase
echo "hello world" | tr -d 'o'                   # Deletes all 'o's
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# echo "hello world" | tr '[:lower:]' '[:upper:]'
HELLO WORLD

┌──(root㉿localhost)-[/home/kali]
└─# echo "hello world" | tr -d 'o'
hell wrld
```

*   The first `tr` command converted the stream to pure uppercase. The second command used the `-d` flag to delete every 'o' character.

## 5. Formatting & Sizing

### split -l

If a file is too massive to upload or process, `split` breaks it down into smaller chunks based on the number of lines (`-l`).

**Syntax:**
```bash
split -l [number_of_lines] large_file prefix_name
```

**Example:**
```bash
split -l 1000 massive_log.txt chunk_
```

*   This command takes `massive_log.txt` and generates multiple new files (`chunk_aa`, `chunk_ab`, etc.), each containing exactly 1,000 lines.

---

### truncate -s

The `truncate` command shrinks or extends the size of a file to a specified byte size (`-s`). It is incredibly useful for clearing out bloated log files without deleting the file itself.

**Syntax:**
```bash
truncate -s [size] filename
```

**Example:**
```bash
truncate -s 0 /var/log/syslog
```

**Output:**
```bash
┌──(root㉿localhost)-[/var/log]
└─# truncate -s 0 syslog
┌──(root㉿localhost)-[/var/log]
└─# ls -lh syslog
-rw-r----- 1 syslog adm 0 Aug 17 11:30 syslog
```

*   The `truncate -s 0` command safely emptied the syslog file, reducing its size to 0 bytes without breaking file permissions or disrupting the logging service.

---

### echo | fold

The `fold` command wraps input lines to fit a specified width (`-w`). This is useful for formatting long, unbroken strings of text to make them readable.

**Syntax:**
```bash
echo "long_string" | fold -w [width]
```

**Example:**
```bash
echo "abcdefghijklmnop" | fold -w 5
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# echo "abcdefghijklmnop" | fold -w 5
abcde
fghij
klmno
p
```

*   The `fold` command forced a line break exactly every 5 characters.

## 🎯 Final Takeaways

The real power of the Linux command line lies in modularity. No single command does everything, but by connecting `cat`, `grep`, `awk`, and `sort` using the pipe (`|`), you can create complex data extraction pipelines on the fly. 

> **💡 The Data Ninja Checklist:**
> * Need to find a specific error? ➔ `cat file.log | grep "Error"`
> * Need to count how many errors occurred? ➔ `cat file.log | grep "Error" | wc -l`
> * Need to extract just the usernames from a list? ➔ Use `cut` or `awk`.

With data manipulation under your belt, you now have the skills of a true operator. The next step is securing that data by mastering **File Permissions and Ownership**.
