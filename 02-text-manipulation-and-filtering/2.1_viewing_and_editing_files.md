## 📖 Introduction
This module is the engine room of Linux administration. Once you know how to look at your environment, you need to know how to build in it. Here, you will learn how to navigate directories, create and destroy files, move data around, and edit text files directly from the command line.

## 1. Directory Navigation & Utilities

### cd (Change Directory)

The `cd` command is how you move through the filesystem. Using it with specific path shortcuts (like `..` for the parent directory) allows you to jump around quickly.

**Syntax:**
```bash
cd [path]
```

**Examples:**
```bash
cd /var/log      # Moves to a specific directory
cd ..            # Moves up one level to the parent directory
cd ../..         # Moves up two levels at once
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# cd /var/log

┌──(root㉿localhost)-[/var/log]
└─# cd ..

┌──(root㉿localhost)-[/var]
└─# cd ../..

┌──(root㉿localhost)-[/]
└─# 
```

*   The terminal prompt automatically updates to reflect your new location after every `cd` command.

---

### echo & clear

`echo` is used to print text or variables to the terminal. `clear` (as covered previously) wipes the screen clean.

**Syntax:**
```bash
echo "text"
```

**Example:**
```bash
echo "Hello, Linux!"
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# echo "Hello, Linux!"
Hello, Linux!
```

*   The `echo` command prints exactly what was placed inside the quotes to the standard output.

---

### help & man

When you forget how a command works, `help` provides a quick summary, while `man` opens the full manual page.

**Syntax:**
```bash
command --help
man command
```

**Example:**
```bash
mkdir --help
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# mkdir --help
Usage: mkdir [OPTION]... DIRECTORY...
Create the DIRECTORY(ies), if they do not already exist.
...
```

*   The `--help` flag outputs a quick, readable cheat sheet for the specified command directly in the terminal.

## 2. File & Directory Creation & Wildcards

### mkdir (Make Directory)

Used to create new, empty folders.

**Syntax:**
```bash
mkdir directory_name
```

**Example:**
```bash
mkdir project_files
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# mkdir project_files
┌──(root㉿localhost)-[/home/kali]
└─# ls
project_files
```

*   The `mkdir` command creates the `project_files` directory in the current location.

---

### touch & Brace Expansion

The `touch` command creates empty files. You can also use **Brace Expansion** `{}` to create multiple files at once.

**Syntax:**
```bash
touch filename
touch prefix{start..end}
```

**Example:**
```bash
touch file{1..5}.txt
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali/project_files]
└─# touch file{1..5}.txt
┌──(root㉿localhost)-[/home/kali/project_files]
└─# ls
file1.txt  file2.txt  file3.txt  file4.txt  file5.txt
```

*   By using `{1..5}`, the system automatically expanded the command and generated five sequentially named files instantly.

---

### Wildcards (ls file*)

Wildcards like the asterisk (`*`) act as placeholders for any unknown characters. This is incredibly useful for filtering files.

**Syntax:**
```bash
command keyword*
```

**Example:**
```bash
ls file*
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali/project_files]
└─# ls file*
file1.txt  file2.txt  file3.txt  file4.txt  file5.txt
```

*   The `*` wildcard tells the system to list anything that starts with "file", regardless of what comes after it.

## 3. Moving, Copying & Deleting

### cp (Copy - Two Uses)

The `cp` command copies files. It can be used to duplicate a file in the same folder (Use 1) or copy a file into a completely different folder (Use 2).

**Syntax:**
```bash
cp source destination
```

**Examples:**
```bash
cp file1.txt backup.txt         # Use 1: Duplicate and rename
cp file1.txt /home/kali/Desktop # Use 2: Copy to another directory
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali/project_files]
└─# cp file1.txt backup.txt
┌──(root㉿localhost)-[/home/kali/project_files]
└─# ls
backup.txt  file1.txt
```

*   The `cp` command created an exact clone of `file1.txt` and named it `backup.txt`.

---

### mv (Move & Rename - Two Uses)

The `mv` command physically moves a file. If you move a file into the *same* directory but give it a new name, it acts as a rename command.

**Syntax:**
```bash
mv source destination
```

**Examples:**
```bash
mv backup.txt old_backup.txt    # Use 1: Rename the file
mv old_backup.txt /tmp          # Use 2: Move the file to another folder
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali/project_files]
└─# mv backup.txt old_backup.txt
┌──(root㉿localhost)-[/home/kali/project_files]
└─# ls
file1.txt  old_backup.txt
```

*   The `mv` command successfully renamed `backup.txt` without leaving a copy of the original file behind.

---

### rm & rmdir (Remove)

These commands are used to delete data. `rmdir` safely deletes *empty* folders. `rm` deletes files. Adding `-r` (recursive) forces `rm` to delete a folder and absolutely everything inside it. **Use `rm -r` with extreme caution.**

**Syntax:**
```bash
rm filename
rmdir empty_folder
rm -r folder_with_files
```

**Example:**
```bash
rm -r project_files
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# rm -r project_files
┌──(root㉿localhost)-[/home/kali]
└─# ls
Desktop  Downloads
```

*   The `rm -r` command completely wiped out the `project_files` directory and all the text files that were inside it.

## 4. Viewing Data

### cat

Dumps the entire contents of a file to the screen at once.

**Syntax:**
```bash
cat filename
```

**Example:**
```bash
cat /etc/hostname
```

**Output:**
```bash
┌──(root㉿localhost)-[/etc]
└─# cat hostname
localhost
```

*   The `cat` command instantly outputs the server's hostname configuration.

---

### less & more

Used for reading large files interactively. `more` allows you to scroll down, but `less` is the modern upgrade that allows scrolling both up and down.

**Syntax:**
```bash
less filename
```

**Example:**
```bash
less /var/log/syslog
```

*(Opens a paginated view where you can use arrow keys. Press `q` to quit).*

---

### head -n & tail -n

Used to view just the beginning (`head`) or the very end (`tail`) of a file. The `-n` flag specifies exactly how many lines you want to see.

**Syntax:**
```bash
head -n [number] filename
tail -n [number] filename
```

**Example:**
```bash
tail -n 3 /var/log/auth.log
```

**Output:**
```bash
┌──(root㉿localhost)-[/var/log]
└─# tail -n 3 auth.log
Aug 17 10:40:01 localhost CRON[4521]: pam_unix(cron:session): session opened for user root
Aug 17 10:45:15 localhost sudo: suryansh : TTY=pts/0 ; COMMAND=/bin/su
Aug 17 10:45:15 localhost su[4600]: Successful su for root by suryansh
```

*   The `tail -n 3` command filters out the noise and only shows the last three entries of the log file.

## 5. Comparing Files

### cmp (Compare)

Compares two files byte by byte. If they are identical, it outputs nothing. If they differ, it tells you exactly which byte and line the first difference occurs on.

**Syntax:**
```bash
cmp file1 file2
```

**Example:**
```bash
cmp v1.txt v2.txt
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# cmp v1.txt v2.txt
v1.txt v2.txt differ: byte 14, line 2
```

*   The `cmp` command detected that the files are different starting at the 14th byte on line 2.

---

### diff -u (Difference Unified)

While `cmp` just tells you *where* they differ, `diff -u` outputs a highly readable "unified format" showing you exactly *what* text was added or removed between the two files.

**Syntax:**
```bash
diff -u file1 file2
```

**Example:**
```bash
diff -u config_old config_new
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# diff -u config_old config_new
--- config_old  2026-08-17 10:30:00.000000000 +0530
+++ config_new  2026-08-17 10:35:00.000000000 +0530
@@ -1,3 +1,3 @@
 Server=localhost
-Port=80
+Port=443
 Timeout=30
```

*   The `diff -u` output uses a `-` to show what was deleted (Port 80) and a `+` to show what was added (Port 443).

## 6. Text Editors

### nano

`nano` is a beginner-friendly, modeless text editor built right into the terminal. All shortcuts are visible at the bottom of the screen.

**Syntax:**
```bash
nano filename
```

**Example:**
```bash
nano index.html
```

*(Opens the file. You can start typing immediately. Press `Ctrl + O` to save, and `Ctrl + X` to exit).*

---

### vi (Visual Editor)

`vi` (or `vim`) is the hardcore, universal text editor found on every Unix system in the world. It uses "modes." You cannot type normally until you enter Insert Mode.

**Syntax:**
```bash
vi filename
```

**Example:**
```bash
vi script.sh
```

**How to survive `vi`:**
1. When it opens, you are in **Command Mode**. You cannot type text.
2. Press `i` to enter **Insert Mode**. Now you can type text normally.
3. Press `Esc` to return to **Command Mode**.
4. Type `:wq` and press `Enter` to save (Write) and exit (Quit). Type `:q!` to exit without saving.

## 🎯 Final Takeaways

Mastering these foundational commands is the most critical step in your Linux journey. You now have the power to navigate your system seamlessly, construct and dismantle directory structures, and inspect or modify files on the fly. 

> **💡 Pro-Tips for the Command Line:**
> * **Double-check your path:** Always run `pwd` before executing destructive commands like `rm -r`.
> * **Be mindful of outputs:** Use `less` instead of `cat` when dealing with large log files so you do not flood your terminal window.
> * **Learn to survive in `vi`:** You might prefer the ease of `nano`, but `vi` is guaranteed to be installed on every single Linux server you will ever manage.

With file management and text editing locked down, you are ready to move on to the next level: piping commands together to filter and transform raw data.
