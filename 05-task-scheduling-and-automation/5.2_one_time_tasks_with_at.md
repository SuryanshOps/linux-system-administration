## 📖 Introduction
A true system administrator does not manually run updates at 3:00 AM. They tell the server to do it for them. Task automation allows you to schedule scripts, commands, and maintenance tasks to execute in the background at specific times without any human intervention.

This module focuses on the `at` command, which is used for scheduling tasks that need to happen exactly once in the future.

---

## 1. One-Time Task Scheduling (`at`)

The `at` command reads commands from standard input and groups them together as an "at job" to be executed exactly once at a specified time in the future.

### Scheduling a Job

To schedule a job, type `at` followed by the target time. This will open an interactive prompt (`at>`) where you can type the commands you want to run. When you are finished, press `Ctrl + D` to save and exit.

**Syntax:**
```bash
at [time/date]
```

**Example:**
```bash
at 10:00 PM
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# at 10:00 PM
warning: commands will be executed using /bin/sh
at> apt update && apt upgrade -y
at> reboot
at> <EOT>
job 1 at Tue Aug 18 22:00:00 2026
```

*   The system has successfully scheduled job number 1. At exactly 10:00 PM, the server will update its packages and reboot without you needing to be logged in. *(Note: `<EOT>` appears when you press `Ctrl + D` to save).*

---

## 2. Viewing and Removing Jobs (`atq` & `atrm`)

You can view your pending one-time jobs with `atq` (at queue) and delete a mistaken job using `atrm` (at remove) followed by the job number.

**Syntax:**
```bash
atq
atrm [job_number]
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# atq
1       Tue Aug 18 22:00:00 2026 a root
┌──(root㉿localhost)-[/home/kali]
└─# atrm 1
```

*   The `atq` command successfully listed the pending job, and the `atrm 1` command deleted it from the queue before it could run.

---

## 🎯 Final Takeaways

Automation is a core component of server administration. 
*   Use **`at`** when you want to run a heavy script during off-hours, but only need it to happen once.
*   Always verify your scheduled tasks using **`atq`** to ensure you did not accidentally schedule conflicting maintenance windows!
