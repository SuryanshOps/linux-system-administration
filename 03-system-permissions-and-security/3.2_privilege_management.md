## 📖 Introduction
If permissions dictate *what* can be done with a file, privilege management dictates *who* is on the system to do it. As a system administrator, you are responsible for creating user accounts, organizing them into logical teams (groups), and securely accessing remote servers. 

This module covers the core commands used to manage the human (and service) identities on your Linux machine.

---

## 1. Group Administration

It is always best practice to create your groups *before* you create your users, so you can assign users to their respective teams immediately upon creation.

### groupadd

The `groupadd` command creates a new group on the system.

**Syntax:**
```bash
groupadd group_name
```

**Example:**
```bash
groupadd developers
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# groupadd developers
┌──(root㉿localhost)-[/home/kali]
└─# cat /etc/group | grep developers
developers:x:1005:
```

*   The `groupadd` command successfully created the "developers" group, which is verified by searching the `/etc/group` file.

---

### groupdel

The `groupdel` command deletes an existing group. *(Note: You cannot delete a group if it is currently assigned as the primary group of any user).*

**Syntax:**
```bash
groupdel group_name
```

**Example:**
```bash
groupdel developers
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# groupdel developers
```

*   The `groupdel` command silently removes the group from the system.

## 2. User Administration

### useradd

The `useradd` command creates a new user account. By default, it does not create a home folder for the user unless you pass the `-m` (make home directory) flag.

**Syntax:**
```bash
useradd [options] username
```

**Example:**
```bash
useradd -m suryansh
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# useradd -m suryansh
┌──(root㉿localhost)-[/home/kali]
└─# ls /home
kali  suryansh
```

*   The `useradd -m` command created the user account and generated a dedicated `/home/suryansh` directory for them to work in.

---

### usermod -G (Modify User Group)

The `usermod` command modifies an existing user account. The `-G` flag is used to assign a user to supplementary groups. 

*(**Crucial Pro-Tip:** Always use `-aG` instead of just `-G`. The `-a` stands for "append". If you use `-G` without `-a`, it will remove the user from all their other groups and ONLY put them in the new one!)*

**Syntax:**
```bash
usermod -aG group_name username
```

**Example:**
```bash
usermod -aG developers suryansh
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# usermod -aG developers suryansh
┌──(root㉿localhost)-[/home/kali]
└─# groups suryansh
suryansh : suryansh developers
```

*   The `usermod` command successfully added the user `suryansh` to the `developers` group without removing them from their default primary group.

---

### userdel

The `userdel` command deletes a user account. To completely wipe the user's data and their home directory at the same time, you must append the `-r` (remove) flag.

**Syntax:**
```bash
userdel -r username
```

**Example:**
```bash
userdel -r suryansh
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# userdel -r suryansh
userdel: suryansh mail spool (/var/mail/suryansh) not found
┌──(root㉿localhost)-[/home/kali]
└─# ls /home
kali
```

*   The `userdel -r` command deleted the account and entirely erased the `/home/suryansh` directory from the system.

## 3. Session Management

### su (Substitute User)

The `su` command allows you to switch your terminal session to another user without logging out completely. Using `su -` (with the hyphen) simulates a full login, loading that user's specific environment variables.

**Syntax:**
```bash
su - username
```

**Example:**
```bash
su - suryansh
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# su - suryansh

┌──(suryansh㉿localhost)-[~]
└─$ whoami
suryansh
```

*   The `su` command successfully swapped the terminal session from `root` to `suryansh`. Notice how the prompt character changed from the root `#` to the standard user `$`.

---

### exit

Once you substitute into another user account, or connect to a remote server, the `exit` command safely drops you back to your previous session.

**Syntax:**
```bash
exit
```

**Example:**
```bash
exit
```

**Output:**
```bash
┌──(suryansh㉿localhost)-[~]
└─$ exit
logout

┌──(root㉿localhost)-[/home/kali]
└─# 
```

*   Executing `exit` closed the `suryansh` session and returned control back to the `root` administrator session.

## 4. Remote Access

### ssh (Secure Shell)

The `ssh` command is the industry standard for logging into and managing remote Linux servers over a network. All data sent through an SSH connection is heavily encrypted.

**Syntax:**
```bash
ssh username@hostname_or_IP
```

**Example:**
```bash
ssh root@192.168.1.50
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# ssh root@192.168.1.50
root@192.168.1.50's password: 
Linux webserver 6.1.0-9-amd64 #1 SMP Debian 6.1.27-1
Last login: Mon Aug 17 11:45:10 2026 from 192.168.1.10

root@webserver:~#
```

*   The `ssh` command established a secure connection to the remote machine at `192.168.1.50` and provided a remote terminal prompt (`root@webserver`).

---

### scp (Secure Copy Protocol)

`scp` uses the SSH protocol to securely copy files from your local machine to a remote server, or vice versa, over the network. 

**Syntax:**
```bash
scp local_file user@hostname_or_IP:/remote/destination/
```

**Example:**
```bash
scp backup.tar.gz root@192.168.1.50:/tmp/
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# scp backup.tar.gz root@192.168.1.50:/tmp/
root@192.168.1.50's password: 
backup.tar.gz                                 100%   45MB  22.5MB/s   00:02    
┌──(root㉿localhost)-[/home/kali]
└─# 
```

*   The `scp` command securely transferred the `backup.tar.gz` file from the local machine directly into the `/tmp/` directory of the remote server.

---

## 🎯 Final Takeaways

Understanding how to control access to your system is just as important as knowing how to navigate it. 

> **💡 The Admin's Best Practices:**
> * **Never share accounts:** Every human accessing the server should have their own dedicated user account created via `useradd`.
> * **Use Groups for teamwork:** Do not assign permissions directly to a user; assign them to a group, and put users into that group using `usermod -aG`.
> * **Secure your remote access:** Always use `ssh` for terminal management and `scp` for file transfers instead of unencrypted legacy protocols like FTP or Telnet.

Now that you can securely manage users and remote connections, you are ready to tackle the core of server operations in **Module 5: Managing System Processes**.
