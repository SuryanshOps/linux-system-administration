## 📖 Introduction
Linux is inherently a multi-user operating system. To keep users from accidentally (or maliciously) destroying each other's data, Linux uses a strict security model based on **Ownership** and **Permissions**. 

This module teaches you how to read the system's security footprint, decode what permissions are currently active, and modify them to lock down your files or open them up for collaboration.

---

## 1. Decoding the `ls -l` Output

When you run the `ls -l` command, the terminal outputs a detailed line of information. To manage permissions, you must understand how to read this line from left to right.

**Example Output:**
```bash
-rwxr-xr-- 1 suryansh developers 1024 Aug 17 11:30 script.sh
```

### The Breakdown Table:

| Segment | Example | What It Means |
| :--- | :--- | :--- |
| **Type** | `-` | First character: `-` means it is a file. `d` means it is a directory. |
| **Permissions** | `rwxr-xr--` | The next 9 characters dictate exactly who can do what with this file. |
| **Links** | `1` | The number of hard links pointing to this file. |
| **User (Owner)** | `suryansh` | The specific user who created or currently owns the file. |
| **Group** | `developers` | The group assigned to the file. Members share the group permissions. |
| **Size** | `1024` | The size of the file in bytes. |
| **Timestamp** | `Aug 17 11:30` | The date and time the file was last modified. |
| **Filename** | `script.sh` | The actual name of the file or directory. |

---

## 2. The Theory: Users, Groups & Octals

The 9-character permissions string (`rwxr-xr--`) is divided into three equal blocks:
1.  **User (u):** The first 3 characters (`rwx`). Applies *only* to the Owner.
2.  **Group (g):** The middle 3 characters (`r-x`). Applies *only* to the Group.
3.  **Others (o):** The last 3 characters (`r--`). Applies to everyone else.

### The Access Levels
*   **Read (`r`):** Can open and view the file's contents.
*   **Write (`w`):** Can modify, save, or delete the file.
*   **Execute (`x`):** Can run the file as a program or script.

### Binary Octals (The Number System)
System administrators use the **Octal Number System** to assign permissions instantly using math. 

| Value | Permission | Symbol |
| :---: | :--- | :---: |
| **4** | Read | `r` |
| **2** | Write | `w` |
| **1** | Execute | `x` |
| **0** | No Access | `-` |

To calculate a permission block, simply add the numbers together:
*   **7** (4+2+1) = Read + Write + Execute
*   **6** (4+2+0) = Read + Write
*   **5** (4+0+1) = Read + Execute
*   **4** (4+0+0) = Read Only

*When you set permissions, you give three numbers: User, Group, and Other. (e.g., **`755`** = User gets 7, Group gets 5, Others get 5).*

## 3. Modifying Permissions (`chmod`)

The `chmod` (Change Mode) command changes the access permissions of files.

### chmod (Octal Method)
This is the fastest and most common way to set permissions in a professional environment.

**Syntax:**
```bash
chmod [octal] filename
```

**Example:**
```bash
chmod 755 script.sh
```

**Output:**
```bash
┌──(root㉿localhost)-[/home/kali]
└─# ls -l script.sh
-rw-r--r-- 1 root root 1024 Aug 17 11:15 script.sh

┌──(root㉿localhost)-[/home/kali]
└─# chmod 755 script.sh

┌──(root㉿localhost)-[/home/kali]
└─# ls -l script.sh
-rwxr-xr-x 1 root root 1024 Aug 17 11:15 script.sh
```

### The Recursive Flag (`-R`)
If you want to change the permissions of a folder *and every single file inside it* at the same time, use the `-R` (Recursive) flag. *(Note: It must be a capital R).*
```bash
chmod -R 755 /var/www/html/
```

## 4. Modifying Ownership (`chown` & `chgrp`)

Even if a file has the right permissions, it might belong to the wrong person. 

### chown (Change Owner & Group)
You can change the User and the Group at the exact same time by separating them with a colon (`:`).

**Syntax:**
```bash
chown user:group filename
```

**Example:**
```bash
chown suryansh:developers server_config.conf
```

**Output:**
```bash
┌──(root㉿localhost)-[/etc]
└─# ls -l server_config.conf
-rw-r--r-- 1 root root 4096 Aug 17 11:20 server_config.conf

┌──(root㉿localhost)-[/etc]
└─# chown suryansh:developers server_config.conf

┌──(root㉿localhost)-[/etc]
└─# ls -l server_config.conf
-rw-r--r-- 1 suryansh developers 4096 Aug 17 11:20 server_config.conf
```

*(Note: Just like `chmod`, you can use `chown -R user:group folder/` to recursively change ownership of an entire directory).*

## 5. Advanced Permissions (SUID, SGID, & Sticky Bit)

When checking file permissions using the `ls -l` command, advanced permissions alter the standard output. Instead of displaying the usual `x` (execute bit), the system replaces it with either an `s` or a `t`.

### Quick Reference Table
| Feature | Target Identity | Letter | Octal Prefix | Core Purpose |
| :--- | :--- | :---: | :---: | :--- |
| **SUID** | User (Owner) | `s` | `4` | Run executable as the file owner. |
| **SGID** | Group | `s` | `2` | Force inherited group ownership in directories. |
| **Sticky Bit** | Others (Public) | `t` | `1` | Prevent unauthorized deletion in shared folders. |

---

### 1. SUID (Set User ID)
*   **Target:** Replaces the **User** `x` with an `s`.
*   **Visual Shift:** `rwxr-xr-x` ➔ `rwsr-xr-x`
*   **How to apply:** `chmod u+s filename` OR `chmod 4755 filename`

> **💡 What it means:** When a standard user runs this file, it executes *as if the file's owner is running it*, not the person who typed the command. For example, the `passwd` command requires root access to write to the password database, so it uses SUID to temporarily grant standard users the power to change their own passwords securely.

### 2. SGID (Set Group ID)
*   **Target:** Replaces the **Group** `x` with an `s`.
*   **Visual Shift:** `rwxrwxr-x` ➔ `rwxrwsr-x`
*   **How to apply:** `chmod g+s directory_name` OR `chmod 2775 directory_name`

> **💡 What it means:** It forces collaboration. Any new file created inside this folder automatically joins the folder's assigned group, rather than the user's personal group. This keeps teamwork smooth because everyone in the group can immediately access the new files without needing an administrator to constantly fix permissions.

### 3. Sticky Bit
*   **Target:** Replaces the **Others** `x` with a `t`.
*   **Visual Shift:** `rwxrwxrwx` ➔ `rwxrwxrwt`
*   **How to apply:** `chmod +t directory_name` OR `chmod 1777 directory_name`

> **💡 What it means:** It acts as a safety guard for deletion. Even though a folder might be wide open for everyone to write files, the `t` means users can **only delete files they personally created**. It stops people from accidentally or maliciously deleting a teammate's files (heavily used on the default `/tmp` directory).

## 🎯 Final Takeaways

File permissions are the primary defense mechanism of a Linux server. A misconfigured permission can either lock critical applications out of their own databases or inadvertently expose sensitive passwords to the public.

> **💡 The Security Checklist:**
> * **`chmod 777` is a last resort:** Never give everyone read, write, and execute access to a file unless absolutely necessary.
> * **Standard Files:** Text files and configurations should generally be `644` (Owner can edit, everyone else can only read).
> * **Standard Directories:** Folders should generally be `755` (Owner has full control, everyone else can read and enter the folder).
